# 電車最速バトル動画ジェネレーター (train-route-race-video)

首都圏の路線図データ(GeoJSON/駅データSHP)を使って、「A駅からB駅まで、
どの路線が一番速いか」を比較する縦動画(1080x1920, ショート動画向け)を
自動生成するツールです。地図上で2つの路線が実際のルート形状に沿って
レースし、通過駅ポップアップ・スコアボード・競馬実況風のテロップ、
実況台本(.txt / .srt)まで一括で作ります。

新宿→藤沢(小田急線 vs JR湘南新宿ライン)の比較動画を題材に作りましたが、
`configs/*.json` を書けば**どの2駅・どの路線の組み合わせでも**汎用的に
使えるように設計してあります。

## できること

(朝ラッシュ比較・運賃比較・普通列車の抜かれ回数の動画も作れます → 「追加ネタ」の章)


- 実在の路線形状(GeoJSON)に沿って2つの経路をレースさせるアニメーション
- 車両アイコンは回転しない(独自イラストへの差し替え可能)
- 主要駅を通過すると「大きく→通常サイズ」でポップアップ表示
- 下部にスコアボード(進捗バー・経過分数)
- 競馬実況風のテロップをテンプレートから自動生成し、動画に焼き込み
- 実況の台本(.txt)と字幕(.srt)を別ファイルでも出力
- 駅データ(SHP)の品質チェックツール付き(後述の「既知の注意点」を参照)

## セットアップ

```bash
git clone <このリポジトリのURL>
cd train-route-race-video

# Python依存パッケージ
pip install -r requirements.txt

# ffmpeg(動画エンコードに必須。pipには無いのでOS側で入れる)
sudo apt-get update && sudo apt-get install -y ffmpeg

# 日本語フォント(Noto Sans CJK)
sudo apt-get install -y fonts-noto-cjk
```

macOSの場合は `brew install ffmpeg` と、日本語フォントは標準搭載のものが
自動的に見つからない場合、`race_video/fonts.py` の `_CANDIDATE_DIRS` に
パスを足すか、環境変数 `RACE_VIDEO_FONT_DIR` でフォントの入っている
ディレクトリを指定してください。

## 使い方

```bash
# 動画生成(30fps, フル画質)
python3 -m race_video.cli configs/shinjuku_fujisawa.json

# 低fpsの高速プレビュー(内容確認用、10fps)
python3 -m race_video.cli configs/shinjuku_fujisawa.json --fast

# 駅データSHPの品質だけチェックしたいとき
python3 -m race_video.cli configs/shinjuku_fujisawa.json --check-stations
```

生成物は `output/` に出力されます:

- `output/<slug>.mp4` … 完成動画
- `output/<slug>_base_map.png` … 背景マップ単体(確認用)
- `output/<slug>_commentary.txt` … 実況台本(タイムコード付き)
- `output/<slug>_commentary.srt` … 字幕ファイル

## 他のルートを追加する方法(汎用化のポイント)

新しい比較動画を作るには `configs/` に新しいJSONを1つ足すだけです。
`configs/shinjuku_fujisawa.json` をコピーして書き換えてください。

```jsonc
{
  "slug": "shibuya_yokohama",              // 出力ファイル名に使われる
  "title_line1": "渋谷 → 横浜",
  "title_line2": "どっちが早い!? 電車最速バトル",
  "start_name": "渋谷",
  "end_label": "横浜",
  "compress_sec_per_min": 0.5,             // 実1分を動画何秒に圧縮するか
  "intro_sec": 2.0,
  "outro_hold_sec": 4.0,
  "routes": [
    {
      "key": "route_a",                    // ルートを識別するキー(a/bなど)
      "name": "東急東横線",
      "short_name": "東急東横線",           // スコアボード等で使う短縮名
      "color": [230, 20, 20],
      "icon_path": "assets/toyoko_icon.png", // 省略可(無ければ簡易アイコン)
      "stations": [
        {"line": "東急東横線", "name": "渋谷", "t_min": 0,  "popup": true},
        {"line": "東急東横線", "name": "武蔵小杉", "t_min": 12, "popup": true},
        {"line": "東急東横線", "name": "横浜", "t_min": 26, "popup": true}
      ]
    },
    { "key": "route_b", "name": "...", "stations": [ ... ] }
  ]
}
```

駅の「並び順」は `stations` 配列の順番がそのまま使われます。`line` には
駅データSHPの `line_name` と完全一致する路線名を指定してください
(一致しないとエラーで教えてくれます)。`t_min` は始発駅からの累積所要時間
(分)で、乗換案内サイト等の実データを参考に入れてください。

途中で別の路線に乗り換える(直通運転含む)場合は、単に `stations` の
`line` を次の駅から新しい路線名に変えるだけです。乗換駅には
`"transfer": true, "transfer_note": "..."` を、乗換なしの直通運転駅には
`"direct_through": true, "transfer_note": "..."` を付けると、実況テロップの
文面が変わります。

`popup: true` を付けた駅だけが動画中にポップアップ表示され、実況の
対象にもなります(あまり多いと画面が窮屈になるので、主要駅だけ絞るのが
おすすめです)。

## configを手入力で作るツール(config builder)

`configs/*.json` を手で書く代わりに、`tools/config_builder.html` を
ブラウザで直接開く(ダブルクリックでOK、サーバー不要)と、GUIで
ルートを組み立てられます。

- ルートごとに路線区間を追加(通常の路線は始点駅・終点駅を選ぶだけ、
  並び順が信頼できない路線は駅を1つずつ選ぶ手動モードに自動で切り替わります)
- 組み立てた駅の一覧から、動画にポップアップ表示したい駅にチェック
- 各駅までの所要時間(分)を手入力(乗換案内サイト等で調べた実データを想定)
- 乗換駅・直通運転駅にはメモを添えられる
- 「JSONを保存」でそのまま `configs/<slug>.json` として使えるファイルを
  書き出し(保存に失敗する環境ではクリップボードへコピーします)

開いた時点で新宿→藤沢の例が読み込まれた状態になっているので、まずは
それを編集しながら使い方を確認してみてください。入力内容はブラウザの
localStorageに自動保存されるので、リロードしても失われません
(「サンプルに戻す」で新宿→藤沢の例にリセットできます)。

## 追加ネタ: 朝ラッシュ比較 / 運賃比較 / 普通列車の抜かれ回数

`configs/*.json` に `"video_type"` を書くと、同じ `race_video.cli` で別ネタの
縦動画(1080x1920)を作れます。地図・陸地・発光ラインの見た目は電車最速バトルと
共通です(`race_video/common.py`)。

| video_type | 内容 | レンダラー | config作成ツール(ブラウザで開くだけ) | サンプルconfig |
|---|---|---|---|---|
| `race`(省略時) | 電車最速バトル | `animate.py` | `tools/config_builder.html` | `configs/shinjuku_fujisawa.json` |
| `rush` | 朝ラッシュと日中で同じ区間の所要時間がどれだけ違うか(複数路線も可) | `rush_video.py` | `tools/rush_builder.html` | `configs/rush_chuo_tokyo_takao.json`, `configs/rush_tokaido_yokosuka.json` |
| `fare` | 競合路線の運賃比較(鳥瞰図で高さ=運賃の壁→重ね合わせグラフ→最終運賃) | `fare_video.py` | `tools/fare_builder.html` | `configs/fare_shinjuku_fujisawa.json` |
| `overtake` | 普通列車が終点までに何本に抜かれるか | `overtake_video.py` | `tools/overtake_builder.html` | `configs/overtake_keikyu_shinagawa_yokohama.json` |

```bash
python3 -m race_video.cli configs/rush_chuo_tokyo_takao.json --fast
python3 -m race_video.cli configs/fare_shinjuku_fujisawa.json
python3 -m race_video.cli configs/overtake_keikyu_shinagawa_yokohama.json
```

出力は従来と同じく `output/<slug>.mp4` と `output/<slug>_base_map.png`、
ナレーション用の台本 `output/<slug>_script.txt` です。`web/app.py` の
「JSONを貼り付けて生成」にもそのまま貼り付けられます(車両アイコンの差し替えにも対応)。

**サンプルconfigの時刻・運賃はすべて動作確認用の仮の値です。** 動画にする前に、
実際の時刻表・運賃検索で調べた値に書き換えてください。

### rush(朝ラッシュ vs 日中)

- 同じ駅の並び(`stations`)を、2本の列車(`runs`)が**同時にスタート**したとして並走
  させます。線路の左右に1本ずつずらして描くので、同じ線路でも重なりません。
- 下のパネルに2つの時計(実際の時刻が進む)・経過分・進捗バー。速い方がゴール
  すると、遅い方に「+N分」が増えていきます。主要駅(`popup`)では遅い方が通過した
  時点の差を表示。最後に所要時間・差・何%増しのRESULT。
- `runs[].times` は駅名→時刻("07:30")。**始発駅と終着駅だけ必須**で、途中駅は
  省略すると距離に比例して補完します。
- `runs[].train_type` に種別(例: `"快速"` `"中央特快"` `"通勤快速"`)を書くと、
  車両アイコンの隣に種別の一文字バッジ(先頭1文字。`type_badge` で変更可)が出て、
  下のパネル・凡例・RESULTにも種別名が入ります。省略時はアイコンの隣に
  `badge`(朝/昼)を表示します。
- **複数路線の比較**(最大3路線): `stations` / `runs` を路線ごとに `lines` に入れると、
  「朝の東海道線 vs 昼の東海道線」「朝の横須賀線 vs 昼の横須賀線」のように路線ごとに
  朝と日中を並走させ、RESULTで「ラッシュでいちばん遅くなる路線」と路線ごとの差を
  出します(サンプル: `configs/rush_tokaido_yokosuka.json`)。`runs` の `color` を
  省略すると、路線色(朝)とそれを明るくした色(日中)になります。
  1路線だけの従来の書き方(トップレベルの `stations` / `runs`)もそのまま使えます。

### fare(運賃比較)

標準は下の「鳥瞰図(3D)版」です。config の書き方(運賃・距離など)は共通で、以下の 1〜3 は
`"view": "2d"` にしたときの平面版の流れです。

1. 地図フェーズ: 各ルートの車両が同じペース(km基準)で進み、`fare` を書いた駅を
   通過すると駅のそばに「駅名 ¥xxx」がポップアップ。下の棒グラフもその駅までの
   運賃にカウントアップしながら伸びます。
2. 距離グラフ: 横軸=距離・縦軸=運賃の階段グラフを描き、`compare_km`
   (例 `[10, 20, 30]`、省略時は自動)の位置で、各ルートのその距離に一番近い駅の
   運賃を表にして比べます。`"show_distance_chart": false` で省略できます。
3. 最終運賃: 終着駅までの運賃を ¥0 からカウントアップし、差額(往復の差も)と
   1kmあたりの運賃を表示。
- 駅の `fare` は円の数値。始発駅は0扱い、**終着駅の `fare` は必須**。
  `fare` の無い駅は経路の形を作るだけで画面には出ません。
- 駅に `"km"`(始発駅からの距離。営業キロなど)を書くと、距離グラフ・同距離比較・
  1kmあたり運賃にその値を使います。書いていない駅は前後の手入力値の間を線路データの
  距離の比で補います(1つも無ければ線路データ上の距離)。車両の動きは常に実際の線形に沿います。
- **距離運賃表から計算する書き方**(駅ごとの運賃を調べなくてよい): ルートに `fare_tables` を書くと、
  各駅の `km`(始発駅からの営業キロ)から運賃を自動で計算します(ビルダーでは「距離と運賃表から計算」)。
  ```json
  "fare_tables": [{"name": "JR東日本", "table": [[3, 150], [6, 190], [10, 210]]}],
  "stations": [{"line": "...", "name": "新宿"}, {"line": "...", "name": "渋谷", "km": 3.4}, ...]
  ```
  - **JR東日本の幹線運賃(2026年3月改定後)はプリセットで入っています**(`data/fare_tables.json`)。
    `{"preset": "jre_kansen_ic"}`(IC運賃)/ `{"preset": "jre_kansen_ticket"}`(きっぷ運賃)と書くだけで使えます。
    ビルダーでは「運賃表を呼び出す」から選べ、ルート名に「JR」が入っていれば最初から入ります。
    2026年3月の改定で山手線内・電車特定区間は幹線に統合されています。地方交通線を含む区間は営業キロでなく運賃計算キロを入れてください。
    よく使う他社の表も同じ形式で `data/fare_tables.json` に足せば、Pythonとビルダーの両方で使えます(足したら `python3 tools/build_builders.py`)。
  - `table` の各行は `[何kmまで, 運賃]`。km の端数は切り上げて表に当てます(`"km_round": "none"` で切り上げなし)。
  - 会社をまたぐ(乗り継ぐ)ルートは表を複数書き、乗り換え駅に `"company": "東急"` と書くと、
    その駅から先はその会社の表で計算して会社ごとの運賃を足します(乗継割引は考えません)。
  - 駅に `fare` を書くとその値を優先します(加算運賃などの例外用)。表から計算するときは全駅が運賃駅になり、
    地図に駅名と運賃が出るのは `"popup": true` の駅と終着駅です。
  - `km` の無い駅は線路データの距離から補うので、少なくとも終着駅の営業キロは入れてください。

#### 鳥瞰図(3D)版(標準)

**運賃比較の動画は鳥瞰図版が標準です**(`race_video/fare3d_video.py`)。以前の平面版と同じ
config がそのまま使えます(サンプル: `configs/fare_shinjuku_fujisawa.json`)。

1. オープニング: 画面中央に大きくタイトル(`title_line1` / `title_line2`、上の小見出しは
   `title_kicker`、省略時「IC運賃くらべ」など)→ 上部の見出しへ移動
2. 鳥瞰図: 地図を斜め上から見下ろし、線路の上に **高さ=運賃** の壁が伸びていく。
   運賃が上がる駅で段が上がり、主な駅に「駅名 ¥運賃」。カメラはゆっくり回り込む
3. たたむ: 壁がほどけて(先に距離方向、少し遅れて運賃方向)重ね合わせの階段グラフに倒れ込む
4. グラフ: 横軸=距離・縦軸=運賃。主な駅名・終点の運賃(安い方を手前に描画)。
   `compare_km`(例 `[10, 20, 30]`)があれば「約10km」などの目印線を引く
5. 最終運賃のカウントアップ

駅名・金額は先に置いた文字と重ならない位置を探して置き、置けないものは省略します。
既定のフレームレートは **60fps**(`"fps"` で変更可、`--fast` は20fps)。
カメラは `camera_az_start` / `camera_az_end`(回り込みの角度、度)・`camera_elevation`(見下ろす角度)、
長さは `title_sec` / `map_sec` / `morph_sec` / `chart_sec` / `final_sec`(秒)、グラフ見出しは `chart_title` で変えられます。

以前の平面版(地図+棒グラフ+距離グラフ)を使いたいときだけ、config に `"view": "2d"` を書いてください
(平面版の `show_distance_chart` などはその場合のみ有効)。

### overtake(普通列車は何本に抜かれる?)

- 普通列車(`local`)は各駅で**減速→停車→加速**(台形の速度パターン)します。
  後ろから来る列車(`passers`)は通過駅を止まらずに走り、`{"arr","dep"}` を
  書いた駅だけ停車します。
- 車両アイコンの隣に**種別一文字のバッジ**(`badge`: 普/快/特/急 …)。普通列車は
  線路の左側、追い抜く列車は右側のレーンに描きます。
- 追い抜かれた瞬間に「抜かれた! 快特」+ 上部のカウンターが増え、長く止まる駅
  (1.5分以上)では「◯◯で待避 N分」を表示。
- 画面下には時間-距離の**ダイヤグラム**をリアルタイムで描き、スジが交わった
  点(=抜かれた所)に黄色い印。最後に何本目に・どこで抜かれたかの一覧。
- 時刻の書き方:
  - 普通列車: `"10:02"` はその駅の**発車**時刻(到着は `default_dwell_sec` 秒前と
    みなす)。待避駅は `{"arr": "10:09", "dep": "10:13"}`。始発は発車、終着は到着。
  - 追い抜く列車: `"10:05"` は**通過**時刻(始発駅なら発車、終着駅なら到着)。
    停車駅は `{"arr": "...", "dep": "..."}`。時刻の無い駅は距離比例で補完。
- 抜かれた判定は「後ろにいた列車が普通列車より前に出た瞬間」を0.02分刻みで
  調べています(CLI実行時にも一覧を表示)。

### 車両アイコン(assets/ のPNG)

3ネタとも、列車ごとに `"icon_path": "assets/xxx.png"` を書くと、その透過PNGが
車両アイコンになります(進行方向=右向き推奨、回転はしません)。種別一文字の
バッジはアイコンの隣に付きます。大きさは `"icon_width": 86`(px、省略時86)で変えられます。

| video_type | 書く場所 |
|---|---|
| `rush` | `runs[]`(複数路線なら `lines[].runs[]`) |
| `fare` | `routes[]` |
| `overtake` | `local` と `passers[]` |

ビルダーでは各列車の「車両アイコン」欄に `assets/xxx.png` を入れるか、「PNGを選ぶ」で
ファイルを選ぶと `assets/<ファイル名>` が入ります(プレビュー表示用で、画像そのものは
JSONに入りません)。**同じPNGをリポジトリの `assets/` に置いてから**生成してください。
見つからない場合は警告を出して標準の簡易アイコンで描きます。`web/app.py` の画面から
アイコンをアップロード・選択することもできます。

### config作成ツール(ビルダー)について

**動画生成サーバー(web/app.py)からも開けます。** `python3 web/app.py` を起動したPCと
同じネットワークにあるスマホ・PCから **`http://<そのPCのIPアドレス>:8080/builders`** を開くと
4つのビルダー(駅レース・朝ラッシュ・運賃・抜かれ回数)が一覧で出ます。IPアドレスは
Ubuntuなら `hostname -I` で確認できます(例: `http://192.168.0.12:8080/builders`)。
サーバーから開いた朝ラッシュ・運賃・抜かれ回数のビルダーには「このPCで使う」欄が出て、

- **configsに保存** … 作ったJSONをそのPCの `configs/<slug>.json` に直接保存
- **保存して動画を生成** … 保存してそのまま動画生成。完成したらダウンロードリンクが出る

が使えます。車両アイコン欄には、そのPCの `assets/` にあるPNGが候補として出ます。
つながらないときは、Ubuntuのファイアウォールで8080番を開けてください
(`sudo ufw allow 8080/tcp`)。

`tools/rush_builder.html` / `fare_builder.html` / `overtake_builder.html` は
サーバー不要の1ファイルHTMLで、Claude Artifactとしても動きます。路線と区間を
選ぶと駅の一覧が出るので、時刻や運賃を入れるだけでconfigのJSONができ、
プレビュー(経過時間グラフ / 運賃の階段グラフ / ダイヤグラムと抜かれ回数)で
動画にする前に中身を確認できます。

ビルダーの元ファイルは `tools/src/` にあります。編集したら次のコマンドで
駅データ(`tools/config_builder.html` から抽出)を埋め込んだ完成版を作り直します。

```bash
python3 tools/build_builders.py
```

## 経路データのクリーニングについて

`routes.geojson` には、複数の物理経路をデータ生成時に結合した際の
継ぎ目と見られる「同じ地点を一瞬だけ往復してしまう」重複区間が、ごく
一部の路線(例: 湘南新宿ラインの横浜駅付近)に混入していました。放置すると
動画中で車両アイコンが一瞬だけ後ろに戻って見えてしまうため、
`race_video/route_builder.py` の `remove_backtracking()` が、経路を
組み立てるたびに自動でこの種の重複・孤立ノイズ頂点を取り除きます
(本物の急カーブは区別して残します)。特定の路線に対する特別扱いでは
なく、どの区間を組み合わせても同じロジックが適用されます。

## 「東海道本線」「高崎線」「宇都宮線」のような愛称路線について

駅データ(`data/stations_shp`)には「東海道本線」「高崎線」「宇都宮線」という
路線名は存在せず、これらの区間はすべて「上野東京ライン」という1つの路線名の
中に(複数の系統が混線した状態で)含まれています。そのため config の
`"line"` にこれらの名前を書いても、実データ上は見つかりません。

`race_video/route_builder.py` の `LINE_ALIASES` が、これらの愛称を実際に
座標・線形データを持つ路線名(上野東京ライン)に自動変換してから駅位置・
線形を引くので、config 上は気にせず `"東海道本線"` `"高崎線"` `"宇都宮線"`
と書いて構いません(表示名としてもそのまま使われます)。config builder
(駅レースビルダー)側にも、この3路線は駅の並び順が確定した状態
(範囲選択できる清潔な路線)としてあらかじめ登録してあります。

同様の理由で「常磐線」「埼京線」はすでに単独の路線として正しい並び順で
登録されています。「湘南新宿ライン」「上野東京ライン」自体は複数系統が
分岐・合流する関係で並び順が一意に決まらないため、config builder では
引き続き駅を手動で順番に指定する方式(プリセットからまとめて読み込み、
不要な駅を削除するのがおすすめ)を使います。

## 途中駅の所要時間(t_min)を空欄にする

停車・乗換をしない単なる通過駅は、config の `t_min` を `null`(または
キーそのものを省略)にしてかまいません。`route_builder.py` が、実際に
組み立てた経路上の距離(km)に比例させて自動的に補完します。ただし
「最初の駅」と「最後の駅」の `t_min` は自動補完できないため、必ず数値を
入れてください(省略するとエラーになります)。config builder(駅レース
ビルダー)側でも、途中駅の所要時間欄は空欄のままで生成できます。

## データについて

- `data/routes.geojson` … 首都圏52路線の線形状(LineString/MultiLineString)
- `data/stations_shp/tokyo_stations.*` … 61路線分の駅データ(Shapefile。
  フィールドは `line_name, stn_name, seq, cum_km, color`)

### 既知の注意点(駅データSHPの品質)

`python3 -m race_video.cli <config> --check-stations` で全路線の品質を
チェックできます。61路線中59路線は駅の並び順(seq)・距離(cum_km)・座標が
正確でしたが、以下の2路線だけ複数の物理系統(例: 小田原方面と宇都宮方面)
の駅が1本のseq/cum_kmに混線しており、**並び順をそのまま信用できません**
(駅名→座標の対応自体は正しいので、座標の引き当てには使えます)。

- 湘南新宿ライン
- 上野東京ライン

原因は、これらの路線が `routes.geojson` 上でMultiLineString(=複数の
物理系統に分かれた線形状)になっており、系統をまたいで駅が最近傍の
頂点にマッチングされてしまったためと推測されます。この2路線を経路に
含める場合は、本ツールの設計どおり `stations` 配列で実際の停車順を
明示的に指定してください(`configs/shinjuku_fujisawa.json` のJR側が実例です)。

将来的にSHP生成スクリプト側を直すなら、「系統(LineStringのセグメント)
ごとに」駅を割り当て直す形にすると、この2路線も自動生成に使えるように
なるはずです。

## 車両アイコンについて

`icon_path` に透過PNG(進行方向=右向き推奨)を指定すると、その画像が
車両アイコンとして使われます。**回転はさせません**(要件どおり、常に
同じ向きで表示されます)。指定が無い場合は `race_video/animate.py` が
簡易なプレースホルダーアイコンを描画します。`assets/` に画像を置いて
config から参照してください。

## ブラウザから動画生成を実行する(web/app.py)

おすすめの使い方: **JSON作成(駅レースビルダー)はスマホ含めどこからでも、
動画生成は自分のPCで** という役割分担です。駅レースビルダーはブラウザの
Claude Artifactとして動くので場所を選びませんが、動画生成はCPUを使う
重い処理なので、自分のPC(Renderの無料プランよりずっと速い)で実行する
ことをおすすめします。

```bash
pip install -r requirements.txt   # Flaskが追加されています
python3 web/app.py
# http://127.0.0.1:8080 を開く
```

「① JSONを用意して生成」では、駅レースビルダーからダウンロードした
JSONファイルを選ぶか、クリップボードに貼り付けるかたちで読み込めます。
「② 保存済みの設定から生成」では `configs/*.json` が一覧表示されます。
どちらも「生成する」を押すとバックグラウンドで
`python3 -m race_video.cli configs/<slug>.json` が実行されます。生成中は
数秒おきに状況をポーリングし、完了すると `output/` にできたmp4をそのまま
ブラウザからダウンロードできます。「低画質プレビュー(高速)」に
チェックを入れると `--fast` オプション(10fps)で素早く確認できます。

**出力ファイル名を指定する**: 「出力ファイル名(任意)」欄に入力すると、
configの `slug`(`configs/<slug>.json` という保存先ファイル名)とは
別に、好きな名前のmp4として出力できます(例: `新宿藤沢_対決版`)。
空欄なら従来通りslugがそのままファイル名になります。CLIから直接実行
する場合は `python3 -m race_video.cli configs/xxx.json --out-name 好きな名前`
のように指定します。

Dockerfileの `CMD` はデフォルトでこのWebページを起動するようになって
いるので、Renderなどにデプロイしてブラウザ経由で動画生成することも
引き続き可能です。ただし無料プランはCPU・メモリの制限が厳しいため、
基本的には自分のPCでの実行をおすすめします。

**生成中にサーバーが再起動してしまった場合について**: メモリ・CPUの
制限が厳しい環境(Renderの無料プランなど)では、生成中にプロセスごと
再起動されてしまうことがあります。この場合、以前は「エラー: not found」
という分かりにくい表示になっていましたが、現在は job_id と出力ファイル名
の対応をファイルに残しておき、(1) 出力ファイルがすでに完成していれば
自動的に「完成」扱いに復旧し、(2) 完成していなければ「サーバーが再起動
された可能性があります」という分かりやすいメッセージを表示するように
しています。それでも頻発する場合は、自分のPCで実行するか、
「低画質プレビュー(高速)」を使ってみてください。

## 実況テロップについて

`race_video/commentary.py` が実況台本(`output/<slug>_commentary.txt`)と
字幕ファイル(`output/<slug>_commentary.srt`)を常に生成しますが、動画
本編への焼き込み(テロップ表示)はデフォルトでは行いません。動画内に
テロップを表示したい場合は、configに `"show_captions": true` を追加して
ください。

## Renderへのデプロイ手順

1. このリポジトリをGitHubにpush(または本READMEにある手順でアップロード)
   しておく。
2. [Render](https://render.com)にログインし、ダッシュボードで
   「New +」→「Web Service」を選ぶ。
3. 連携したGitHubアカウントからこのリポジトリを選択する。
4. Runtimeを **Docker** にする(Render側で `Dockerfile` が自動検出され、
   `ffmpeg` ・ `fonts-noto-cjk` ・ Python依存パッケージが全部インストール
   される)。
5. プラン(Instance Type)は、試すだけなら **Free** で問題ありません。
   ただしFreeプランは15分アクセスが無いとスリープし、次のアクセス時に
   起動し直すので、久しぶりにアクセスすると最初の表示が少し遅くなります。
6. 「Create Web Service」でデプロイを開始する。ビルドに数分かかります。
7. 完了すると `https://<サービス名>.onrender.com` のようなURLが発行される
   ので、そこを開けば動画生成ページが表示されます。

**注意点**: Renderの無料プランのストレージはコンテナの再起動・再デプロイ
のたびにリセットされます(ディスクを追加していないため)。生成した動画は
その場でダウンロードしてください。もし複数人で使う・過去の動画も残して
おきたい、といった要件が出てきたら、Render の Web Service に永続ディスク
(Persistent Disk)を追加する、またはS3などの外部ストレージに保存する形に
拡張できます。

## 今後の拡張(バックエンド化)

- `race_video/route_builder.py` の `build_all_routes()` が「発駅・着駅
  ->経路」の中核ロジックです。ユーザー入力(発駅・着駅)から
  `stations` 配列を自動組み立てする層(経路探索)を追加すれば、
  `build_all_routes()` 以降はそのまま再利用できます。
- `web/app.py` はconfigを選んで実行するだけの最小構成なので、
  `tools/config_builder.html` で作ったJSONをアップロードしてその場で
  configとして保存 → 即生成、という流れに拡張することもできます。
